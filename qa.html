About this page

Northbank Sports Hub is a fictional sports centre website made for a web design assignment. This page explains the whole project in question and answer form: what it is, how it was designed and built, how the booking system works, how it was tested and what its limits are. It is written so that anyone can understand it, and so that a marker can ask about any part and find the answer.

The questions are grouped by topic. Use the search box to find one, or open a topic from the list. Every question has its own web address, so a link such as qa.html#price-calc opens straight to it.

Source code: GitHub repository. Live website: GitHub Pages.

Try it in two minutes

  1. Book a pitch: pick a date and a time, watch the price and the free places change, then press Confirm booking.
  2. Open My bookings. Your booking is there. Try Cancel booking: the page says whether it is free or a late fee.
  3. Book again with the member number NBM-0001. 15% comes off the hire price.
  4. On the Events page, see the places left. The tennis championships entries are full.
  5. Send a message, then open the Staff dashboard to see your booking, the message and the member.
  6. Use Reset demo data (under Demo tools) to start again.

The project at a glance

What it is, who it is for and what it is made of.

What is this project in one minute?

Northbank Sports Hub is a complete, working website for a made-up community sports centre. A visitor can read about sports events, check prices, look at the facilities, book a pitch, court, lane or room, buy event tickets, join as a member, cancel a booking and send a message. A second, hidden-from-the-menu page shows the same activity from the staff side.

It is written in plain HTML, CSS and JavaScript. There is no framework, no build step and no server. Everything a visitor enters is saved in their own browser.

Why is the centre fictional?

The task was a web design assignment, so the centre, people, prices, events, phone number and email address are all invented. The email domain ends in .example and the phone number is from the range reserved for drama, so nothing can reach a real person. The terms and privacy pages are sample text, not legal advice.

Who is the website for?

Three kinds of visitor: local people who want to book a pitch or court after work, families and schools looking for events and a pool, and club organisers who need to hire a space or enter a team. That is why the home page shows the next events and the booking button first, and why the prices are one click away.

Which technologies are used, and why those?
  • HTML for structure and meaning.
  • CSS for layout, colour and responsiveness. One file, assets/css/style.css.
  • JavaScript (plain, no libraries) for the booking logic, availability, the saved data and small helpers.
  • SVG for every picture, so there are no photos to license and the images stay sharp at any size.
  • localStorage as the stand-in for a back end.
  • GitHub Pages to host it for free.

Nothing needs installing: a browser is enough, which also makes it easy to explain and to mark.

Was an AI tool used to build it?

Yes. The assignment allowed asking an AI, and this site was built with an AI coding assistant (Claude Code) working from the marking sheet. The person submitting it is expected to understand it and be able to explain it, and this Q&A page exists to make that easy. Every behaviour described here can be checked on the live site or in the files.

Why no framework such as React, and no library such as jQuery?

The site is small enough that a framework would add more to learn and explain than it saves. Plain files load fast, work offline from a folder, need no build step and are easy to host. It also keeps the whole thing readable: each script is short and does one job.

Design and look and feel

Why the site looks the way it does.

What is the design idea?

The idea is a multi-sport hall floor. In a real sports hall, the lines for basketball, badminton and volleyball are painted over each other in different colours. The site does the same: each sport has its own line colour (green for football, blue for badminton, teal for swimming, red for basketball, a tennis-ball yellow-green for tennis, orange for running), and that colour is used for event tags, event rows, price dots and tiles. The hero picture is the hall floor itself.

How were the colours chosen and are they readable?

A deep navy ink colour carries the text on a pale grey-blue page, with the sport colours used as accents. They are stored once as CSS custom properties at the top of the stylesheet, so a change there changes the whole site. The text and button colour pairs were checked with a small contrast script against the WCAG AA level (at least 4.5 to 1 for normal text). Meaning is never carried by colour alone: statuses always have a word as well, such as Confirmed or Cancelled.

Which fonts are used?

No font files are downloaded. Headings use a condensed system font stack (Bahnschrift, then similar fonts, then Arial) and the body uses the system's own UI font. That keeps pages fast and avoids sending visitors' data to a font service. The trade-off is that the exact letter shapes differ a little between Windows, macOS and Linux.

How is navigation kept easy?
  • The same header on every page, with the current page marked (aria-current) and a Book now button in it.
  • Breadcrumbs under the page title, so you always know where you are.
  • A footer on every page with the main pages, the opening hours, My bookings and a button to this Q&A.
  • A logical flow: Home, Events or Facilities, Prices, Book, Summary, My bookings.
  • On phones the menu folds into a Menu button that also closes with the Escape key.
  • A custom 404 page that links back into the site.
Where do the pictures come from?

They were drawn for this site as SVG files: a top-down court or pool for each facility, the hero hall floor, a logo, a favicon and a map. Because they are drawings, there are no copyright problems, they are tiny (the whole assets/img folder is under 60 KB), and they scale to any screen without going blurry. Each has a descriptive alt text.

Is there a dark mode?

No. The site declares a light colour scheme and was designed and checked for contrast in that one scheme. A dark theme would be a good next step: because the colours are CSS custom properties, it would mostly mean redefining the values inside a prefers-color-scheme: dark block and re-checking contrast.

HTML: structure and tags

The marking sheet asks for creative, correct HTML.

Which HTML tags are used beyond div and span?

Structure: header, nav, main, section, article, aside, footer. Content: figure with figcaption, picture with source, address, blockquote, time, mark, details with summary, dl with dt and dd. Tables: caption, thead, tbody, th scope. Forms: fieldset, legend, label, output, select, textarea and input types for email, tel, date, number, search and checkbox. Plus noscript for visitors without JavaScript.

What is semantic HTML and why does it matter?

Semantic HTML means choosing the tag that describes what the content is, not just how it should look. A nav is navigation, a time is a date a computer can read, an address is contact information. It matters because screen readers and search engines use those meanings, because keyboard users can jump between landmarks, and because the page still makes sense with the CSS switched off.

Why use the time tag with a datetime attribute?

People read "Sat 5 Dec 2026", but a computer needs a fixed format. <time datetime="2026-12-05"> gives both: the visible text for people and the standard date for browsers, search engines and assistive technology.

Why is the price shown in an output tag?

output is the element made for the result of a calculation. The booking form recalculates the price every time you change a choice, and output tells assistive technology that this value is a computed result.

What does the picture tag do?

It lets the browser choose between images. On the home page, phones get hero-hall-close.svg, a tighter crop of the hall floor that stays readable on a narrow screen, while larger screens get the full picture. This is called art direction: a different crop, not just a smaller copy of the same image.

How do the question-and-answer boxes open without JavaScript?

They are details and summary elements. The browser itself opens and closes them, and they work with the keyboard and with screen readers. This page's JavaScript only adds the search box and the Expand all and Collapse all buttons on top.

How are headings and landmarks organised?

Each page has exactly one h1 and the levels never skip (h1, then h2, then h3). Landmarks (header, nav, main, footer) have labels where there is more than one navigation. A "Skip to main content" link is the first thing a keyboard user reaches. The checker script in tools/ tests the single h1 and the heading order on every page.

How are the forms built?
  • Every field has a visible label tied to it with for and id.
  • Related fields are grouped in a fieldset with a legend.
  • The browser checks the basics for free: required, type="email", number ranges and the date minimum and maximum.
  • autocomplete values let browsers fill in name, email and phone.
  • Where the standard checks are not enough (is this time free? does this member number exist?), JavaScript sets a custom message with setCustomValidity, so the browser shows it in the same way as its own messages.

CSS and responsive design

Two marks on the sheet are for responsiveness.

How is the site responsive?

It is built mobile first: the base CSS is the phone layout, and two min-width media queries add the tablet layout (from 40em, about 640 px) and the desktop layout (from 62em, about 992 px). On top of that, fluid sizing with clamp() lets headings and spacing grow smoothly, and CSS Grid and Flexbox let rows wrap or stack when there is no room. Images have a width and height and max-width: 100%, so nothing overflows the screen.

Which three screen sizes were tested?
  • Phone: 375 px wide.
  • Tablet: 768 px wide.
  • Desktop: 1280 px wide.

Screenshots of the home page at all three sizes are in the README (docs/screenshots). To see it yourself, open the site and drag the window narrower, or press F12 and use the device toolbar. Nothing should scroll sideways at any width.

How do the wide price tables work on a phone?

A table with five columns cannot fit in 375 px. On phones, the CSS turns each row into a small card, and every cell shows its column name beside the value using the data-label attribute (td::before reads it). On tablets and desktops the same HTML shows as a normal table, so there is only one version of the content to maintain.

How do images behave on different screens?

They are SVG, so they scale without losing sharpness. Each has width and height attributes, so the browser reserves the right space before the image loads and the page does not jump. Pictures below the first screen use loading="lazy", and the hero uses fetchpriority="high" because it is the first thing seen.

What are CSS custom properties and where are they used?

They are variables in CSS, such as --ink or --blue, defined once in :root and used with var(--ink). The sport colours use them in a clever way: each element gets data-sport="tennis" and CSS sets --sport from that, so a tag, a border and a dot all pick up the right colour from one attribute.

Where are Grid and Flexbox used?

Grid is used for two-dimensional layouts: the footer columns, the event rows, the facility sections and the booking page with its price panel beside the form. Flexbox is used for one-dimensional rows: the header bar, button rows and the filter chips. The price panel on the booking page is position: sticky on desktop, so the total stays in view while you fill in the form.

How is the hero picture animated, and what about people who dislike motion?

The court lines in hero-hall.svg are drawn in as if painted, using CSS inside the SVG (stroke-dashoffset from 1 to 0 over about one and a half seconds). It plays once. Inside the same file, a prefers-reduced-motion: reduce rule turns it off for visitors who asked their system for less motion, and smooth scrolling is only enabled when that preference is not set.

Is there a print style?

Yes. A @media print block hides the header, the footer and the rows of buttons, switches to a white page and tightens the spacing, so the booking summary prints as a clean confirmation. The Print this summary button on the summary page calls window.print().

How do you stop the page scrolling sideways?

By not letting anything be wider than the screen: no fixed pixel widths on containers, images limited with max-width: 100%, flex and grid rows that wrap, and the few things that are naturally wide (tables) inside their own scrolling container. Every page was checked at 375 px for horizontal scroll.

The booking system: what works and how

The part that makes it more than a brochure.

How does a booking work, step by step?
  1. You choose Hire a facility or Event tickets on the booking page.
  2. For a hire, you pick the facility, date, start time, length and how many pitches, courts or lanes. The page checks opening hours, closed days and what is free, and shows a live price.
  3. You add your details and press Confirm booking.
  4. The page checks everything one more time, makes a reference such as NB-4K7Q2M, saves the booking in the browser and opens the summary page for that reference.
  5. The booking now counts against availability, appears on My bookings and on the staff dashboard, and can be added to a calendar or cancelled.
Does it have a back end?

Not a server. A real back end is a program on a server with a database, and nothing like that is available on free static hosting. Instead, the site has a small browser back end: store.js is a data layer that saves JSON in localStorage, and the other scripts talk to it through functions such as Store.bookings.add() and Store.members.find(). It does what a back end does (saves, finds, updates and deletes records, and enforces rules like capacity), it just keeps the data on the visitor's own device.

That has one important consequence: data is per browser. A booking made on a phone is not visible on a laptop, and the staff dashboard only shows what was created in that same browser.

What is localStorage, and how is it different from sessionStorage and cookies?
Three ways a browser can keep data

Bookings must survive closing the tab, so localStorage was the right choice. The first version of this site used sessionStorage, which is why the summary used to disappear; it was changed for exactly that reason.

What exactly is saved, and under which names?

Four items, all with the prefix nb: so they never clash with another site's data: nb:bookings (a list of booking records), nb:members (member numbers), nb:messages (contact messages) and nb:seeded (a flag so the demo member is only created once). Each is a JSON string. You can see them in your browser's developer tools under Application, then Local Storage.

What is JSON?

JSON is a text format for data made of objects, lists, text, numbers and true or false, for example {"ref":"NB-4K7Q2M","total":90}. localStorage can only keep text, so the scripts turn data into JSON text with JSON.stringify when saving and back into objects with JSON.parse when reading. It is also the format almost every real web API uses.

What if the browser blocks storage?

Some private windows or strict settings block localStorage. The store tests for this when the page loads. If it is blocked, the site keeps data in memory for as long as the page stays open, shows a warning on the pages that need storage, and the booking form refuses to pretend a booking was saved: it tells the visitor to allow site data or to phone instead.

How is the price worked out?

The hire price is counted hour by hour. Each hour is peak or off-peak: weekday hours from 17:00 and every weekend hour are peak, earlier weekday hours are off-peak. The two totals are multiplied by the number of pitches, courts or lanes. A member number takes 15% off that hire subtotal. The equipment pack (£6) is added last, so it is never discounted.

Worked example: a 5-a-side pitch on a Wednesday from 16:00 to 18:00 is one off-peak hour (£38) plus one peak hour (£52) = £90. With a valid member number, 15% (£13.50) comes off, so £76.50. This is the same example printed on the Prices page, and the same function produces both numbers.

How do you make sure the Prices page and the booking form never disagree?

Two things work together. First, every script reads its prices from one file, assets/js/data.js, so the booking form, the summary page and the staff dashboard cannot disagree with each other. Second, the Prices page is plain HTML that people read, so its numbers are typed into the tables. The test file tools/test_logic.js reads both and fails if any hire price, ticket price, entry fee or membership fee on the Prices page differs from data.js. It runs on GitHub on every push, so a mismatch is caught before the site goes live.

How does availability work?

Two things use up space:

  1. Real bookings made in this browser. They are read from the store, so a booking really does take a pitch away from the next person.
  2. Simulated other customers. A real centre would already have bookings from strangers. The site fakes that with a fixed formula based on the date, hour and facility, so the same slot always gives the same answer. Weekday evenings (17:00 to 21:00) and weekend middays (10:00 to 16:00) are the busy times.

For a multi-hour booking, the number free is the smallest number free in any of its hours. The start-time drop-down shows each time as free, only some free, full, closed or passed, and full times cannot be chosen.

Is the availability real? Isn't that cheating?

Part of it is simulated, and the site says so openly (see the limits question below). Without a server there is no way to know what strangers booked, so the simulation makes the demo behave like a busy centre instead of an empty one. The logic that uses it is real: the same code would work unchanged if the "other customers" came from a database. What is not simulated is every booking you make yourself.

What is the shared sports hall rule?

Basketball and badminton use the same hall floor, so they cannot happen at once. The basketball court is only free when no basketball and no badminton court is booked in that hour, and badminton courts are only free when basketball is not booked. Book the basketball court at 18:00 and every badminton court at 18:00 shows as full, and the page explains why.

Can two people book the same slot?

In one browser, no: the second booking sees the first and is refused once the places run out. Across two different devices, yes, because they have separate stores and no server to compare them. That is the main reason a real site needs a real back end, which checks and saves bookings in one place in a single step.

How do event places and entries work?

Every event has a spectator capacity and, where people can enter and play, an entry capacity. Some places are already sold, so the numbers feel real: for example the Winter Five-a-side Cup has 16 team places and 14 are taken, so 2 are left. The Club Tennis Championships entries are full, so only spectator tickets can be bought. Your own bookings add to the sold numbers. Events whose last day has passed are marked finished and cannot be booked. The Events page and the booking form show the same "places left" because both ask the same function, NBAvail.eventStatus().

How are tickets counted?

Adult, concession and under-12 tickets count as one person each; a family ticket counts as four (up to 2 adults and 2 children). Under-12 tickets are free but still need a ticket, so they use up a place. Events marked free have all spectator tickets at £0, but an entry fee still applies if you enter to play.

How do member numbers and the discount work?

On the Prices page, the Join online form creates a member and shows a number such as NBM-1001 (numbers start after 1000 and go up by one). The booking form has a Member number box. As you type, it looks the number up in the saved members and tells you straight away: either "Member found: name. 15% off hire is applied." or that the number does not exist, in which case the form will not submit. A built-in demo member, NBM-0001, lets a marker try it without joining.

The discount is real arithmetic in the price calculation, and the member number is saved with the booking so the summary and the staff dashboard can show it. No payment is taken; joining is a demonstration.

How does cancelling work?

It follows the Terms and conditions. A hire booking can be cancelled for free if at least 48 hours remain before it starts. An event booking needs 7 days. If you cancel later, the site still lets you cancel (so the place is freed for someone else) but records that the full price is still due as a late fee, and says so before you confirm. After a booking has started it cannot be cancelled. Cancelling asks for confirmation first, and a cancelled booking immediately stops counting against availability.

How is the booking reference made?

It is NB- followed by six characters picked at random with crypto.getRandomValues. The letters and digits that are easy to mix up (0, O, 1, I, L) are left out so it is easy to read out over the phone. The store checks that the reference is not already used before keeping it.

How does the summary page know which booking to show?

The address carries the reference: confirmation.html?ref=NB-4K7Q2M. The page reads ref from the address with URLSearchParams and looks it up in the store. That is why the page still works after a reload, from a bookmark, or from the link on My bookings. If the reference is not in this browser's store, it says so and links back.

What does Add to calendar do?

It builds an .ics file, the standard calendar format, entirely in the browser: the booking is turned into text lines such as BEGIN:VEVENT, DTSTART and SUMMARY, wrapped in a Blob and downloaded. Google Calendar, Apple Calendar and Outlook can import it. A two-day event, such as the tennis championships, gets one calendar entry per day. Times are local clock times, so they show correctly wherever the visitor is.

What does the staff dashboard do?

It is the other side of the system. It reads the same store as the booking form and shows totals, a searchable and filterable bookings table, event capacity, messages from the contact form and the member list. Staff can check a booking in, cancel it (which frees the space), mark messages as read or delete them, and export the bookings as a CSV file for a spreadsheet. Anything you do on the public pages appears there at once.

Is the staff dashboard secure?

No, and it does not pretend to be. There is no login, because without a server there is nothing to check a password against, and the page says it is a demonstration. In a real site, the dashboard would sit behind a staff login and the data would come from a server, which refuses requests from anyone who is not signed in.

What is special about the CSV export?

Spreadsheets treat any cell starting with =, +, - or @ as a formula, which could be used to run something nasty from a name someone typed into a form (CSV injection). The exporter puts an apostrophe in front of such cells and escapes quotes, so a name is always shown as plain text.

What happens when someone sends a message on the contact page?

The message is checked by the browser, saved in nb:messages with a status of new, and a thank-you panel replaces the form. Nothing is emailed, because a static site cannot send mail. The staff dashboard lists it, and staff can mark it read or delete it.

What does Reset demo data do?

It clears the four saved items and puts the demo member back, so the site returns to a clean state, for example before a presentation. It sits in Demo tools on My bookings and on the staff dashboard, and asks for confirmation inside the page, because it cannot be undone.

Can I open the site straight from the folder, without a web server?

Yes, for reading every page. For the booking system it depends on the browser. Chrome, Edge and Brave let all local files share one saved-data area, so bookings work. Firefox may keep each local file's data apart, so a booking made on one page might not be found on the next. In that case, use the live website, or start a tiny local server inside the project folder with python3 -m http.server and open http://localhost:8000. The booking pages show a short notice when they detect they were opened from a folder.

Does the site work without JavaScript?

All the information pages work with JavaScript off: the content is plain HTML, the Q&A boxes open natively and links work. The pages that need to run code (booking, summary, My bookings, the staff dashboard) say so and give the phone number instead. Extras like the event filter and the join form are only shown when JavaScript is available. This approach is called progressive enhancement: start with something that works for everyone, then add features for browsers that can run them.

What is the DOM and how does the code use it?

The DOM (Document Object Model) is the browser's live tree of the page. JavaScript finds elements (document.getElementById), reads and changes them (textContent, hidden, disabled) and listens for events such as input, change, click and submit. The booking form listens for any change and recalculates the price, the availability and the validation messages every time.

Why is every script wrapped in a function that calls itself?

The pattern (function () { ... }()); keeps variables private to each file, so two scripts can both have a variable called form without clashing. Each file shares only what it needs by attaching one object to window, such as window.NBStore or window.NB. It was chosen over ES modules so the site also works when you open the files straight from a folder, where browsers block module imports.

How does the code avoid cross-site scripting (XSS)?

XSS happens when text typed by a user is inserted into the page as HTML, so a name like <img onerror=...> would run code. Here, anything that came from a user (names, emails, notes, messages) is only ever put on the page with textContent, or through the small helper NB.el(), which sets text as text. The one place that uses innerHTML restores a fixed hint written by the site itself, not user input. There are no third-party scripts, no eval and no inline event handlers.

Where is the form validated, and is that enough?

In the browser, in two layers: the built-in HTML checks (required fields, email format, number limits) and custom checks in booking.js (opening hours, closed days, availability, member number, event places). It is enough for a demonstration, but not for a real shop: a visitor can change anything in their own browser's developer tools, so a real site must repeat every check on the server and recalculate the price there. The browser checks are only there to help honest users get it right quickly.

How does the code deal with dates and times?

Dates are kept as plain YYYY-MM-DD text and built into dates with the year, month and day as separate numbers, which avoids the time-zone shifts that happen when a date string is parsed as UTC. Opening hours are checked as whole hours. Weekends are found with getDay(). The booking date is limited by the date field's min (today) and max (one year ahead).

What is the formula behind the simulated availability?

It is a small text hash (FNV-1a, a few lines of code). The text "use|pitch|2026-12-02|18" is turned into a number between 0 and 1, and if that number is below the chance of being busy (about 55% in busy hours and 20% in quiet ones), the facility is used by a stranger. Because the same text always gives the same number, the answer never changes between visits, and no random numbers or saved data are needed.

Accessibility, privacy and security

Making it usable and safe for everyone.

What accessibility features does it have?
  • A skip link, landmarks and one h1 per page.
  • Visible keyboard focus on every control, and everything can be used without a mouse.
  • Labels on every form field, error messages written in words, and a live region (aria-live) that announces availability changes.
  • aria-expanded on the menu button, and focus moved to the confirmation or the success message after an action.
  • Descriptive alt text for each picture, and tables with a caption and th scope.
  • Colour contrast checked against WCAG AA, and statuses that always include a word.
  • Reduced-motion support: the hero animation and smooth scrolling switch off for visitors who ask for less motion.
What personal data is collected, and where does it go?

Name, email, optional phone and notes, when someone books, joins or sends a message. It is saved only in that visitor's browser (localStorage) and never leaves the device. There are no cookies, no analytics, no adverts and no third-party requests of any kind. The Privacy page says the same, and Reset (or clearing the site data in the browser) removes it all.

Is anything sensitive stored?

No passwords, no payment details and no ID documents. localStorage can be read by any script on the same site and by the person using the browser, so it is only suitable for things like these demonstration bookings. Nothing is taken online: payment is at the front desk.

Could someone change the data or the prices in the browser tools?

Yes, and that is a good question to raise. Anything that runs in the browser can be edited by the person using it. For this demonstration, that only affects their own copy. In a real shop, the server must hold the real prices and availability and recalculate the total itself, never trusting a total sent from the page.

Does the site load anything from other websites?

No. Fonts, images, scripts and styles are all local files, so there is nothing to track visitors, nothing that can break when another service goes down, and no cookie banner is needed.

Testing and quality checks

How we know it works.

How was it tested?
  • Screenshots at phone, tablet and desktop widths in a real browser, checked page by page (and the home page also in Firefox).
  • Automated logic tests for the price rules, availability, the saved data and the cancellation rules. Run them with node tools/test_logic.js.
  • End-to-end checks in a headless browser that fill in the real forms: book, view the summary, cancel, join, send a message and read it on the staff dashboard.
  • A page checker (python3 tools/check_site.py .) that checks every page's structure, links, images and labels, and runs on GitHub on every push.
  • A contrast script for the colour pairs.
Was the HTML validated?

The page checker catches the common mistakes the validator would: unbalanced or misplaced tags, duplicate ids, missing alt or labels, skipped heading levels, broken links and anchors. For the official check, paste the live address into the W3C validator at validator.w3.org.

Which browsers does it work in?

It was checked in Chromium (Chrome, Edge and Brave use the same engine) and Firefox. It uses only long-established features, so recent versions of Safari should be fine too, but it was not tested there.

What was the hardest part?

Keeping a lot of rules consistent without a server: the same price on the Prices page, the booking form and the summary; the same "places left" on the Events page and in the form; a hall that two sports share; and making cancelled bookings free their space again everywhere. The answer was to put each rule in exactly one function and have every page call it.

On GitHub Pages, which serves static files for free. A workflow in .github/workflows/pages.yml runs on every push to the main branch, copies the HTML files and the assets folder into a clean folder, and publishes that. All links in the site are relative, so it works at an address like username.github.io/repository-name/.

What are Git and GitHub?

Git is the tool that records every version of the files, so changes can be compared and undone. GitHub is a website that stores a Git project online and can host it. The repository holds the pages, scripts, styles, images and workflows, and the README explains how to run and change the site.

The MIT licence: anyone may use, copy and change the code, as long as the licence notice stays with it. It suits a small learning project. The invented names, prices and events carry no real meaning.

Limits and what comes next

What it does not do, and how it could grow.

What is not real?
  • There is no server, so data lives in one browser and is not shared across devices or people.
  • Other customers' bookings are simulated by a formula.
  • No payment is taken and no email or text message is sent.
  • The staff dashboard has no login.
  • Member numbers only work in the browser that created them (apart from the demo member).
  • The centre, its events, prices and contact details are made up.

The site says so wherever it matters, so nobody is misled.

How would you turn it into a real full-stack site?
  1. Replace store.js with calls to a server API (for example POST /api/bookings, GET /api/availability). The rest of the site would keep working, because it only talks to the store through a handful of functions.
  2. Run a server (Node.js, Python or similar) with a database such as PostgreSQL or MongoDB for bookings, members and messages.
  3. Check availability and calculate the price on the server, in one database transaction, so two people cannot book the same slot.
  4. Add staff login, with passwords stored hashed, and protect the dashboard routes.
  5. Add online payment through a provider, and confirmation emails.
  6. Keep the browser checks, because they give instant feedback, but never rely on them.
What would you improve with more time?
  • A dark theme using the existing colour variables.
  • A weekly calendar view of availability.
  • Rescheduling a booking, not only cancelling it.
  • A waiting list for full events.
  • More automated browser tests, run on every push.
  • Real photos, with responsive srcset images, if the centre supplied them.
What would you do differently?

Decide the data model (what a booking, member and event look like) before drawing any page, because every page then reads from it. This project ended up there, but in a later step. The first version also kept the summary in sessionStorage, and moving to a store with references and statuses was the change that made cancelling, availability and the dashboard possible.

Quick answers to common exam questions

Short definitions, with an example from this site.

What does mobile first mean?

Writing the CSS for the smallest screen first, then adding rules for larger screens with min-width media queries. Here the phone layout is the default, and tablet and desktop layouts add columns on top.

What is a media query?

A CSS rule that only applies when a condition is true, usually the screen width. @media (min-width: 62em) { ... } applies its rules from about 992 px wide.

What is an API?

A set of functions or web addresses that one program offers to another. NBStore.bookings.add() is a small API: the booking form does not know how data is saved, only which function to call. A real site would offer an API over the internet and keep the same shape.

What is an event listener?

A function the browser calls when something happens, such as a click or a change. form.addEventListener('input', update) runs update every time anything in the booking form changes.

What is progressive enhancement?

Building so the basics work everywhere, then adding extras where the browser supports them. The information pages are plain HTML. JavaScript adds the filter, the live price and the saved bookings.

What is CRUD, and where is it in this project?

Create, Read, Update, Delete: the four basic things you do with stored data. Create is a new booking, read is My bookings, update is a booking's status changing to cancelled or checked in, and delete is removing a message or resetting the demo.

What is the difference between front end and back end?

The front end is what runs in the visitor's browser: the HTML, CSS and JavaScript they see and click. The back end runs on a server: it stores data, checks rules, sends emails and takes payment. This project has a complete front end and a back end that is simulated inside the browser.

What is accessibility and why does it matter?

Making the site usable by people with different abilities and devices: screen readers, keyboard only, low vision, motor difficulties, small screens. It matters because everyone benefits and in many places it is a legal duty. Examples here: labels on all fields, visible focus, enough contrast, alt text.
